## 3. Area yang Sudah Diaudit dan Terbukti Baik (Tidak Ada Masalah)

1. **Alur Login SCELE & Pembuatan UID/Token (`server.js:53-60, 118-134`, `authMiddleware.js`):**
   - Username SCELE dinormalisasi (`trim().toLowerCase()`) sesuai perilaku Moodle sebelum di-hash dengan SHA-256 (`scele_<48-hex>`).
   - Password tidak pernah disimpan ke Firestore, tidak pernah dikembalikan di response, dan tidak pernah dicatat ke log.
   - Seluruh endpoint terproteksi memverifikasi Firebase ID Token melalui `auth.verifyIdToken(token)` dan selalu mengambil `uid` dari `req.user.uid`, bukan dari body/query.
2. **Firestore Security Rules (`firestore.rules`):**
   - *Fail-closed* (`allow read, write: if false;` pada wildcard `/{document=**}`).
   - Hanya `userTimelines/{uid}` serta `users/{uid}/activities/{activityId}` (beserta subkoleksi `history`) yang dapat dibaca langsung oleh pemiliknya (`request.auth != null && request.auth.uid == uid`), dan seluruh penulisan dari client ditolak (`allow write: if false`).
   - Koleksi sensitif (`sceleSessions/{uid}`, `scrapeLocks`, `scrapeControls`, `scrapeRuns`, `gradebooks`, `subjects`, `studyPlans`, `taskState`, `academicProfile`) 100% tertutup dari akses client SDK.
3. **CORS & Security Headers (`httpMiddleware.js:18-48`, `config.js:55-86`):**
   - Validator CORS memverifikasi origin secara eksak setelah normalisasi URL, menolak wildcard `*`, kredensial di URL, path non-root, query, hash, dan mewajibkan HTTPS di `staging`/`production`.
   - Security headers (`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Cache-Control: no-store`) terpasang di semua response.
4. **Redaksi Logging & Sanitasi Error (`redaction.js`, `scrapeRunData.js`, `httpErrorMiddleware.js`):**
   - Logger melakukan redaksi rekursif yang tahan referensi sirkular (`WeakSet`), membatasi kedalaman objek, menyensor key sensitif (`password`, `authorization`, `cookie`, `token`, `storageState`, `private_key`, `buffer`, dll.), serta menyensor pola `Bearer ...` dan `PRIVATE KEY` di dalam pesan string maupun `Error.message`.
5. **Formula Injection pada CSV/XLSX (`csvParser.js:6,66`, `xlsxParser.js:169-184`, `importNormalizer.js:77`):**
   - Sel yang diawali `=`, `+`, `-`, `@` ditandai dengan flag `formula: true` dan peringatan `FORMULA_CELL`.
   - Pada XLSX, formula **tidak pernah dievaluasi**; parser hanya membaca nilai *cached* (`raw.result`) jika bukan referensi eksternal (`EXTERNAL_FORMULA_REFERENCE` seperti `[workbook]`, `http://`, `https://`, `file://`, atau UNC path `\\` otomatis dikosongkan nilainya).
6. **Semantik Perhitungan Nilai Inti (`gradeCalculation.js`, `gradeLetters.js`, `semesterPlanner.js`):**
   - Pembedaan antara `scoreStatus: 'known'` dengan `earnedScore: 0` (berkontribusi 0 namun masuk ke `gradedWeight`) vs `scoreStatus: 'pending'` (masuk ke `remainingKnownWeight`) sudah tepat dan konsisten.
   - *Drop-N-lowest* hanya menjatuhkan komponen `known` non-bonus yang belum di-drop manual, selalu menyisakan minimal 1 komponen (`Math.min(requestedDropCount, Math.max(0, candidates.length - 1))`), dan tidak pernah menjatuhkan komponen `pending`.
   - Perhitungan internal menggunakan floating-point penuh tanpa pembulatan dini, menggunakan `EPSILON = 1e-9` untuk perbandingan batas, dan pembulatan hanya dilakukan untuk tampilan (`roundForDisplay`).
7. **Koordinasi Transaksi Distributed Scrape Gate & Task State (`scrapeCoordinationRepository.js`, `taskStateService.js`, `importRepository.js`, `planRepository.js`):**
   - Lock & cooldown `/scrape`, pembaruan array `/task-state/completed`, locking commit import (`lockDraftForCommit` dengan `crypto.timingSafeEqual`), serta penerapan study plan draft (`applyDraft`) semuanya sudah menggunakan transaksi Firestore (`db.runTransaction`) yang idempoten.
